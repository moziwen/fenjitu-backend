# 01｜数据真相与契约

## 核心原则

每一类跨设备共享的业务状态都要指定**唯一权威写入方**。客户端缓存只承担加速展示或断网重试职责，不能与服务端各自计算一份互相冲突的结果。纯界面状态可以留在客户端，不必为了“统一”而全部上送。

## 必须明确的契约

1. 在实现前写明：数据从哪里产生、谁能修改、何时生效、其他设备何时可见。
2. 定义字段语义、类型、可空性、默认值、排序和分页边界；区分“没有记录”“字段缺失”“资源不可访问”。不得用猜测值或拼接地址掩盖缺失。
3. 列表与详情、读与写、多个终端使用同一领域定义。接口返回不应直接暴露数据库行结构；变更字段时要审视全部消费者和历史数据。
4. 明确兼容策略：新增字段尽量向后兼容；删除或改变语义前，列出旧客户端行为、迁移窗口和版本策略。
5. 契约测试覆盖正常、空结果、部分缺失、重复请求、权限边界和分页边界。涉及跨端一致性时，使用同一账号和实体比对服务端结果，而不只比对截图。

## 交付证据

至少留下接口契约、数据来源图或文字说明、典型请求与响应样例，以及覆盖关键边界的测试。若客户端仍保留本地回退逻辑，明确其触发条件与是否允许参与业务判定。
