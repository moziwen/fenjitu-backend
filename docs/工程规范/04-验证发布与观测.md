# 04｜验证、发布与观测

## 分层验证

1. 本地：模型校验、类型检查、自动化测试、构建和关键契约测试。
2. 预发布：以接近生产的数据形态验证迁移、依赖和旧客户端兼容性；涉及媒体时核对真实资源可访问性。
3. 生产：迁移状态、进程状态、存活检查、依赖就绪检查、公开接口与带有效身份的关键业务接口。未登录返回 401 只能证明路由和鉴权存在，不能证明业务可用。

## 发布门槛

- 发布包及目标环境可识别且无密钥；依赖与锁文件一致，迁移工具在目标环境可用。
- 先备份数据库和当前代码，并确认备份位置；再迁移、部署、切流或重启。每个阶段失败都应停止，不得输出“发布完成”。
- 检查命令必须以失败状态结束，例如健康接口非 2xx 或超时不能被后续 `echo` 掩盖。
- 保留可定位的版本、迁移编号、备份目录、发布时间与验证结果。上线后短时观察错误率、重启次数和延迟。

## 排障证据

请求日志至少能关联请求标识、路由、状态码、耗时和适度脱敏的主体标识。不要把健康检查、PM2 在线或旧错误日志中的片段，直接推断为某个用户场景正常或异常；按时间范围与请求标识核对。
