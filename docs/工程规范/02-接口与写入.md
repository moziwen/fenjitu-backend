# 02｜接口与写入

## 接口边界

- 沿用项目既有的路径、版本、响应包裹和错误码约定；集合接口提供稳定排序与有上限的分页。不要为追求形式统一而破坏现有客户端契约。
- 在运行时校验路径、查询和请求体；失败时返回可定位但不泄漏内部实现的错误。日志中的请求标识要能对应客户端错误。
- 鉴权之后仍须检查对象归属与操作权限。用户或租户标识以可信身份上下文为准，不接受客户端自报的归属标识作为授权依据。

## 写入不变量

1. 对可重试写入定义幂等范围：键的作用域、请求内容冲突、过期策略和重复请求的返回值都要明确。不能把“用了幂等键”等同于“业务天然幂等”。
2. 并发修改同一聚合时，选择数据库约束、原子更新、事务锁或版本号保护不变量；在测试中模拟重复与并发请求。
3. 历史状态与新状态分开建模；一个操作只改变它负责的状态，不顺手重置无关进度。需要级联更新时，在契约中说明并放入同一事务或可靠的补偿流程。
4. 审计关键写入的主体、对象、结果和请求标识，但不记录令牌、密码、完整私人数据或不必要的请求正文。

## 完成门槛

代码审查时逐项回答：谁能调用、能改谁的数据、重复调用会怎样、并发调用会怎样、部分失败会怎样、旧客户端会怎样。没有答案的写接口不应直接上线。
