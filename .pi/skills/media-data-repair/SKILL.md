# 媒体与历史数据修复

先读[迁移与数据修复](../../../docs/工程规范/03-迁移与数据修复.md)，再按需要读[数据真相与契约](../../../docs/工程规范/01-数据真相与契约.md)。优先定位根因，不把批量回填当成默认答案。

## 分阶段处理

1. 只读清点：明确资源字段的权威来源、规范路径、可空规则；抽样检查源记录、关联关系、返回映射和资源实际可访问性。
2. 划分异常：从未存在、历史未保存、路径映射错误、资源失效、权限受限或客户端渲染失败。报告每类数量与样本，不展示敏感记录。
3. 需要写入时，先获得修复授权，提供默认预览脚本与精确匹配条件；校验备份，设定批次、幂等策略和失败停止条件。保留既有有效资源，不顺带修改无关业务进度。
4. 执行后复查数据库、接口返回和真实资源；记录处理、跳过与失败数量。

## 风险边界

无法证明目标资源正确或备份可用时，停在诊断。禁止猜造媒体地址、无条件全表更新，或把预览脚本的结果说成已修复。
