# 安全发布与数据库迁移

生产变更具有外部影响，只有用户明确要求部署或迁移时才实施。先读[迁移与数据修复](../../../docs/工程规范/03-迁移与数据修复.md)与[验证发布与观测](../../../docs/工程规范/04-验证发布与观测.md)，再查目标项目实际运维手册；不得照搬其他项目的主机、目录或命令。

## 发布门禁

1. 确认目标环境和发布版本，识别工作区未提交变更并核对发布包内容；明确是否包含客户端发布、种子数据或历史回填，不能因名字相近而顺带执行。
2. 在目标环境只读核对当前版本、迁移状态、依赖和进程。运行本地质量门禁，检查迁移与旧代码的兼容性。
3. 取得并校验数据库和代码备份，记录恢复位置；确认迁移工具与生产依赖可用。缺凭据、备份失败、目标不清或迁移不可逆且无恢复方案时停止。
4. 按项目流程上传、迁移、部署和切换；每步检查退出码。失败后保留现场，按预先确认的回滚方案处理，不自动恢复数据库。
5. 验证迁移状态、进程、存活、依赖就绪及至少一个真实业务路径；缺登录态时明确标为“业务未验证”，不可用 401 代替通过。短时观察新错误和重启情况。

## 交付记录

报告版本、迁移编号、备份位置、各项检查结果和未完成的客户端发布或人工验收。不要在输出中暴露密钥、令牌或数据库连接串。
